Where JavaScript runs

three places, one language
The browser consoleFastest possible feedback. F12 → Console. Type an expression, press Enter, see the value. Use this constantly while reading.
A script in a pageWhat you'll actually ship. The code can reach the DOM and change the page.
Node.jsThe same language outside a browser — servers, build tools, scripts. No DOM there, since there's no page.

Do this now — set up a file to work in

$ mkdir -p ~/code/js-practice && cd ~/code/js-practice $ code .

index.html:

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>JS practice</title> <script src="main.js" defer></script> </head> <body> <h1 id="title">JS practice</h1> </body> </html>

And main.js:

console.log("connected");

Open with Live Server, open the console, and you should see connected. If you don't, the script isn't loading — check the filename and the path before going any further.

Why defer matters

A plain <script> in the head runs before the body exists, so document.querySelector("#title") returns null and everything breaks with a confusing error.

defer tells the browser to download the script immediately but run it after the HTML is parsed. It's the modern default — use it and the problem never arises. The old advice of putting scripts at the end of the body does the same thing more clumsily.

Console tricks worth knowing now

console.log() is the workhorse. console.table() prints an array of objects as an actual table and is dramatically better for data. console.log({user}) — with braces — prints user: {…} so you can see which variable you logged, which matters once you have six logs going.

02

The fast recap — values & flow

chapters 1–2, compressed

If you've read the first two chapters, skim this. If not, it's enough to continue with.

Bindings

const name = "Utkarsh"; // cannot be reassigned. Your default. let count = 0; // can be reassigned. Use when it genuinely changes. var old = "avoid"; // legacy. See section 04.

const does not mean immutable

It means the binding can't be pointed at something else. If it holds an object or array, the contents are still fully changeable:

const list = [1, 2]; list.push(3); // fine — list is still the same array list = [4]; // TypeError: Assignment to constant variable

This trips up almost everyone once, and it's the seed of the confusion that section 09 clears up properly.

The eight types

numberOne type for integers and decimals. 0.1 + 0.2 !== 0.3 — floating point, same as everywhere else.
stringText. Single, double, or backticks for template literals.
booleantrue / false.
undefined"No value has been assigned." What you get from a missing property or a function with no return.
null"Deliberately empty." A value you set on purpose.
objectEverything structured — objects, arrays, functions, dates, regexes.
symbol / bigintRare. Symbols appear briefly in section 16; bigint is for integers beyond 2⁵³.

Truthiness, and the one comparison rule

Eight values are falsy: false, 0, -0, 0n, "", null, undefined, NaN. Everything else is truthy — including "0", [] and {}, which surprises people.

Always use ===

"5" == 5 // true — == converts types first "5" === 5 // false — === compares type AND value null == undefined // true null === undefined // false

The coercion rules for == are genuinely arcane. Use === and !== everywhere and you never have to learn them. The one common exception: x == null is a neat way to check for "null or undefined" at once.

Control flow

if (score > 50) { … } else if (score > 30) { … } else { … } for (let i = 0; i < 5; i++) { … } for (const item of array) { … } // values — use this for arrays for (const key in object) { … } // keys — objects only while (condition) { … } const label = score > 50 ? "pass" : "fail"; // ternary

for…of and for…in are not interchangeable

for…of gives you values and works on arrays, strings, Maps and Sets. for…in gives you keys and is for objects. Use for…in on an array and you get index numbers as strings, plus anything inherited — which is a bug waiting to happen.

03

Functions — three ways

chapter 3 begins
// 1. declaration — hoisted, can be called before it's defined function square(x) { return x * x; } // 2. expression — a function stored in a binding const square = function (x) { return x * x; }; // 3. arrow — shorter, and different about `this` const square = (x) => x * x;
DeclarationHoisted — the whole function is available before the line it's written on. Good for top-level named functions.
ExpressionNot hoisted; exists only after that line runs. Emphasises that a function is just a value.
ArrowConcise, and has no this of its own — which is either the feature you want or the bug you're hunting. Section 15.

Arrow function shapes

(x) => x * x // implicit return — no braces, no `return` x => x * x // one parameter: brackets optional () => 42 // no parameters: brackets required (a, b) => a + b // several parameters (x) => { return x * x; } // braces means you must write `return` (x) => ({ value: x }) // returning an object literal needs parens!

That last one catches everyone

x => { value: x } doesn't return an object. The braces are read as a function body, value: as a label, and the function returns undefined. Wrap the object in parentheses: x => ({ value: x }).

Parameters

function greet(name, greeting = "Hello") { // default value return `${greeting}, ${name}!`; // template literal } greet("Utkarsh"); // "Hello, Utkarsh!" greet("Utkarsh", "Namaskar"); // "Namaskar, Utkarsh!" function sum(...numbers) { // rest: collect the lot into an array return numbers.reduce((a, b) => a + b, 0); } sum(1, 2, 3, 4); // 10

JavaScript never checks your arguments

Call a two-parameter function with five arguments and the extras are silently ignored. Call it with none and the parameters are undefined. No error, ever.

This is flexible and it is also why TypeScript exists. Until you meet TypeScript, default parameters and early guard clauses are your defence.

Do this now — in the console

> const shout = (s) => s.toUpperCase() + "!" > shout("hello") "HELLO!" > shout // no brackets — the function itself (s) => s.toUpperCase() + "!" > typeof shout "function"

Notice that shout without brackets gives you the function as a value. That distinction — the function versus calling the function — is the whole foundation of section 12.

04

Scope, and the var story

where a name is visible

Scope is the region of the program where a binding can be seen. JavaScript has three kinds, and the history matters because you'll read old code.

Global scopeDeclared outside every function and block. Visible everywhere. Minimise these.
Function scopeDeclared inside a function, visible throughout it. What var gives you.
Block scopeVisible only inside the nearest { }. What let and const give you.
function test() { if (true) { var a = 1; // function-scoped — escapes the if block let b = 2; // block-scoped — trapped in the if block } console.log(a); // 1 console.log(b); // ReferenceError: b is not defined }

Inner scopes can see outward

const appName = "ESD"; function outer() { const x = 10; function inner() { const y = 5; return x + y + appName.length; // sees x AND appName } return inner(); } // outer() cannot see y. Visibility only goes outward, never inward.

That chain of enclosing scopes is called the scope chain, and it's exactly what makes closures work in the next section.

Why var is discouraged

It ignores blocksA var inside an if or for leaks out into the whole function.
It hoists as undefinedYou can reference it before its line and get undefined rather than an error — so typos fail silently instead of loudly.
It can be redeclaredvar x twice in the same scope is legal. That's a bug the language should have caught.

let and const hoist too, but into a temporal dead zone — referencing one before its declaration throws a ReferenceError instead of quietly handing you undefined. Failing loudly is the improvement.

The rule

const by default. let when the value genuinely needs to change. Never var in new code.

Defaulting to const isn't pedantry — it means every let in your file is a signal that something mutates there, which is genuinely useful when reading code you wrote a month ago.

05

Closures

the idea people find hardest

The definition

A function remembers the scope it was created in, even after that scope has finished running. A function plus that remembered environment is called a closure.

function makeCounter() { let count = 0; // local to makeCounter return function () { count += 1; return count; }; } const a = makeCounter(); a(); a(); a(); // 1, 2, 3 const b = makeCounter(); b(); // 1 — its own separate count

makeCounter finished running long ago. Normally its local count would be discarded — but the returned function still refers to it, so it survives. And each call to makeCounter creates a fresh one, which is why a and b don't interfere.

Why you'd want one

Private stateData nothing else can reach or corrupt. The counter above.
Function factoriesBuild specialised functions from a general one.
Callbacks that rememberAn event handler that still knows which item it belongs to.
Every React hookuseState is closures. When you learn React, this section is what makes it make sense.

Do this now — a function factory

function multiplyBy(factor) { return (n) => n * factor; // captures `factor` } const double = multiplyBy(2); const triple = multiplyBy(3); double(7); // 14 triple(7); // 21

The classic loop bug — and why let fixed it

for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 100); } // 3, 3, 3 — one shared `i`, and by the time the timeouts fire it's 3 for (let i = 0; i < 3; i++) { setTimeout(() => console.log(i), 100); } // 0, 1, 2 — `let` creates a fresh binding each iteration

This was one of the most-asked JavaScript interview questions for a decade. let in a for loop gets a new binding per iteration, so each closure captures its own copy.

Q1Why can't you read count from outside makeCounter, even though the function you got back can?
Show answer

Scope only looks outward, never inward. The returned function is inside makeCounter's scope, so it can see count. Your code is outside, and there is simply no name bound to that value out there.

The variable is alive — the closure keeps it from being collected — but unreachable except through the function. That's genuine encapsulation with no keyword required.

06

Recursion and the call stack

a function that calls itself
function factorial(n) { if (n <= 1) return 1; // base case — stops the recursion return n * factorial(n - 1); // recursive case — moves toward the base } factorial(5); // 120

Every recursive function needs both

A base case that returns without recursing, and a recursive case that gets measurably closer to it. Miss either and you get RangeError: Maximum call stack size exceeded — the stack overflow.

The call stack

Each call gets a frame on a stack holding its parameters and local variables. Calls push, returns pop. Recursion just means many frames from the same function:

factorial(5) → 5 * factorial(4) ← still waiting → 4 * factorial(3) ← still waiting → 3 * factorial(2) ← still waiting → 2 * factorial(1) → returns 1 ← base case, unwinding starts ← 2 ← 6 ← 24 ← 120

The stack is finite — a few thousand frames deep in most browsers. This is why deep recursion on large inputs is a real constraint in JavaScript, which (unlike some languages) does not reliably optimise tail calls.

When recursion is the right choice

Tree-shaped dataThe DOM, file systems, nested comments, JSON. A tree is defined recursively, so recursive code matches its shape.
Naturally recursive definitionsFactorials, Fibonacci, divide-and-conquer sorts.
Not for simple iterationCounting to a million is a loop. A loop is faster and can't blow the stack.

Do this now — walk the DOM recursively

Paste this into the console on any page. It's short, it's genuinely recursive, and it connects straight back to the tree from the HTML document.

function countElements(node) { let total = 1; // count this node for (const child of node.children) { total += countElements(child); // and everything beneath it } return total; } countElements(document.body);

Six lines to count every element on any page in the world, at any depth. Writing that with loops means managing your own stack of nodes to visit.

07

Arrays

chapter 4
const courses = ["ADB", "DS", "ESD"]; courses[0]; // "ADB" — zero-indexed courses.length; // 3 courses[courses.length - 1]; // "ESD" — last item courses.at(-1); // "ESD" — modern, much nicer courses[10]; // undefined — no error!

Methods that change the array

push / popAdd / remove at the end. Fast.
unshift / shiftAdd / remove at the start. Slower — everything else has to move up.
splice(start, count, ...items)Remove and/or insert anywhere. Returns what it removed.
sort / reverseMutate in place and also return the array, which hides the mutation. See the warning below.

Methods that return something new

slice(start, end)A copy of part of the array. end is exclusive. slice() with no arguments is the classic shallow copy.
concatJoins arrays into a new one. Mostly replaced by spread.
join(sep)Array to string. ["a","b"].join("-") → "a-b".
includes / indexOfSearch. includes returns a boolean and is what you usually want.

slice and splice sound alike and behave oppositely

slice — copies, leaves the original alone. splice — surgery, changes the original.

One letter apart, opposite behaviour. Worth saying out loud a couple of times now to save yourself later.

sort() has two traps

[10, 9, 1].sort(); // [1, 10, 9] ← NOT a mistake [10, 9, 1].sort((a, b) => a - b); // [1, 9, 10] ← correct

Trap one: the default sort converts everything to strings, and "10" sorts before "9" alphabetically. Always pass a comparator for numbers.

Trap two: it sorts in place. If you need the original untouched, copy first — [...arr].sort(…). Modern engines also offer toSorted(), which returns a new array.

Do this now — prove both traps

> const nums = [10, 9, 1, 100] > nums.sort() [1, 10, 100, 9] > nums [1, 10, 100, 9] // the original changed too > [...nums].sort((a,b) => a-b) [1, 9, 10, 100] > nums [1, 10, 100, 9] // this time it didn't
08

Objects

named properties
const student = { name: "Utkarsh", roll: "CS2024", courses: ["ADB", "ESD"], address: { city: "Pune", pin: 411001 }, greet() { return `Hi, ${this.name}`; } // a method };

Reading and writing

student.name; // "Utkarsh" — dot notation student["name"]; // "Utkarsh" — bracket notation const key = "roll"; student[key]; // "CS2024" — brackets take an expression student.key; // undefined — looks for a property literally named "key" student.email = "x@y.com"; // add delete student.email; // remove "name" in student; // true — does the property exist?

When to use brackets

Use dots when you know the property name as you write the code. Use brackets when the name is in a variable, comes from user input, or isn't a valid identifier (obj["first name"]).

That's the entire rule, and "why doesn't obj.key work?" is one of the most common beginner questions.

Useful shorthands

const name = "Utkarsh", roll = "CS2024"; const student = { name, roll }; // same as { name: name, roll: roll } const field = "score"; const result = { [field]: 92 }; // computed key → { score: 92 }

Iterating an object

Object.keys(student); // ["name", "roll", "courses", …] Object.values(student); // ["Utkarsh", "CS2024", …] Object.entries(student); // [["name","Utkarsh"], ["roll","CS2024"], …] for (const [key, value] of Object.entries(student)) { console.log(key, "→", value); }

Object.entries plus destructuring in a for…of is the standard way to loop an object, and it composes with the array methods in section 13.

Arrays are objects

typeof [] returns "object". An array is an object with numeric keys and a length that maintains itself. That's why Array.isArray(x) exists — typeof can't tell you.

References and mutation

the most important section here

This one explains a whole category of bug that otherwise looks like the language is lying to you.

The rule

Primitives are copied by value. Objects and arrays are copied by reference.

Assigning an object doesn't duplicate it. It hands out a second pointer to the same thing.

let a = 1, b = a; b = 2; a; // 1 — untouched const x = { n: 1 }; const y = x; y.n = 99; x.n; // 99 — same object // and comparison follows identity, not contents: { n: 1 } === { n: 1 }; // false — two different objects x === y; // true — same object

Copying properly

// shallow copy — top level only const copy = { ...original }; const copy = Object.assign({}, original); const arrCopy = [...arr]; // deep copy — nested objects too const deep = structuredClone(original); // modern, built in const deep = JSON.parse(JSON.stringify(original)); // old trick

Shallow means one level

const student = { name: "A", address: { city: "Pune" } }; const copy = { ...student }; copy.name = "B"; // fine — student.name is still "A" copy.address.city = "Mumbai"; // student.address.city is ALSO "Mumbai"

The spread copied the reference to the nested address object, not the object itself. For nested data use structuredClone.

The JSON round-trip works but silently destroys functions, undefined, Map, Set, and turns Date objects into strings. It's fine for plain data and wrong for anything else.

Why this shows up everywhere

Passing an object into a function passes the reference, so the function can modify your data. That's occasionally what you want and usually a nasty surprise.

Modern practice leans heavily on not mutating — return a new object rather than editing the one you were given. React depends on this: it decides whether to re-render by comparing references, so mutating state in place means oldState === newState and nothing updates. That specific bug will find you within a week of starting React.

Q2Why does [1,2,3] === [1,2,3] evaluate to false?
Show answer

Because === on objects compares identity, not contents. Those are two separately created arrays that happen to hold the same values, so they're different objects.

To compare contents you need to do it yourself — element by element, or JSON.stringify(a) === JSON.stringify(b) for simple data (which is order-sensitive and slow, but fine for a quick check).

Destructuring, spread, rest

syntax you'll use in every file

Destructuring — unpacking

// arrays — by position const [first, second] = ["ADB", "DS", "ESD"]; const [, , third] = courses; // skip with commas const [head, ...tail] = courses; // head + the rest // objects — by name const { name, roll } = student; const { name: fullName } = student; // rename while unpacking const { grade = "N/A" } = student; // default if missing const { address: { city } } = student; // nested

Where it really pays off is function parameters:

// instead of this function show(student) { console.log(student.name, student.roll); } // do this — the signature documents what it needs function show({ name, roll }) { console.log(name, roll); } show(student);

Spread — unpacking into a new thing

const more = [...courses, "OS"]; // new array with an extra item const merged = [...listA, ...listB]; // concatenate const updated = { ...student, roll: "CS2025" }; // copy + override const combined = { ...defaults, ...userOptions }; // later wins Math.max(...[3, 7, 2]); // 7 — spread into arguments

The update pattern, which you'll write constantly

{ ...state, field: newValue } — copy everything, then override one key. Order matters: whatever comes last wins. This one line is how state updates are written in React, Redux and most modern JavaScript.

Rest — collecting

function log(first, ...others) { … } // others is an array const { name, ...everythingElse } = student; // object rest

Same three dots, opposite jobs. On the left of an assignment or in a parameter list it collects; on the right or in a literal it spreads.

Do this now — remove a key without mutating

const student = { name: "A", roll: "CS1", secret: "xyz" }; const { secret, ...safe } = student; safe; // { name: "A", roll: "CS1" } student; // unchanged

A tidy, non-mutating way to strip a field before logging or sending data somewhere.

11

JSON

objects as text

JavaScript Object Notation — a text format for structured data, based on JavaScript's object syntax but now used by every language. It's what APIs speak.

const json = JSON.stringify(student); // object → string const obj = JSON.parse(json); // string → object JSON.stringify(student, null, 2); // pretty-printed, 2-space indent

How JSON differs from a JS object literal

Keys must be quotedAnd with double quotes. {"name": "A"}, never {name: 'A'}.
Strings use double quotesSingle quotes are invalid JSON.
No trailing commasLegal in JS, a syntax error in JSON. A very common cause of "Unexpected token".
No commentsNone at all.
No functions or undefinedOnly strings, numbers, booleans, null, arrays and objects.

What stringify silently drops

const data = { name: "A", greet() {}, // functions → gone nothing: undefined, // undefined → gone when: new Date(), // Date → an ISO string, not a Date tags: new Set([1, 2]) // Set → {} — empty! }; JSON.stringify(data); // {"name":"A","when":"2026-08-16T09:00:00.000Z","tags":{}}

No warning, no error. This is why the JSON round-trip is a poor deep-copy method for anything but plain data — and why a date that arrives from an API is always a string until you convert it.

Always wrap JSON.parse in try/catch

try { const data = JSON.parse(text); } catch (err) { console.error("Bad JSON:", err.message); }

Any malformed input throws. If that data came from a network request or a file, it will be malformed one day, and an unhandled throw takes down whatever was running.

12

Higher-order functions

chapter 5 — the shift in thinking

The idea

Functions are values. You can store them in variables, put them in arrays, pass them as arguments, and return them from other functions.

A higher-order function is one that takes a function as an argument or returns one. You've already written both — makeCounter returned a function, and setTimeout takes one.

const shout = (s) => s.toUpperCase(); shout; // the function itself — a value shout("hi"); // calling it — the result ["a", "b"].map(shout); // pass the function ✓ ["a", "b"].map(shout()); // calls it immediately, passes the result ✗

The brackets are the whole distinction

onClick={handleClick} passes the function to be called later. onClick={handleClick()} calls it now and passes whatever it returned — usually undefined.

You will make this mistake in React. Knowing the shape of it now saves the twenty minutes of confusion later.

Why bother

Compare a loop with a higher-order call:

// what the computer does const names = []; for (let i = 0; i < students.length; i++) { names.push(students[i].name); } // what you mean const names = students.map(s => s.name);

The second version has no index variable to get wrong, no accumulator to forget to initialise, no off-by-one. It also says transform each item rather than making the reader work that out from the mechanics. That's the argument for the whole style: less room for error, and the intent is on the surface.

Where you'll meet them

Array methods (map, filter, reduce, sort), event handlers (addEventListener), timers (setTimeout), promises (.then), and every React hook. This is not an academic style — it's the ordinary way JavaScript is written.

13

map, filter, reduce

learn these three properly

map — transform every item

const students = [ { name: "A", score: 80 }, { name: "B", score: 45 }, { name: "C", score: 92 } ]; students.map(s => s.name); // ["A", "B", "C"] students.map(s => ({ ...s, passed: s.score >= 50 }));

The callback receives (element, index, array) — take only what you need. And map always returns an array of exactly the same length; if you're not using the return value, you wanted forEach.

filter — keep some

students.filter(s => s.score >= 50); // the two passing students students.filter(Boolean); // drop all falsy values — neat trick

The callback must return truthy to keep the item. It never changes the items themselves.

reduce — collapse to one value

const total = students.reduce((sum, s) => sum + s.score, 0); // ↑ accumulator ↑ initial value // 217

Always pass the initial value

Without it, reduce uses the first element as the starting accumulator and begins at the second — which gives wrong answers for anything that isn't plain addition, and throws TypeError on an empty array.

Passing 0, [] or {} explicitly also documents what type you're building. Make it a habit.

reduce is not only for sums. Anything that folds a list into one thing:

// group by a field — extremely common in real code const byGrade = students.reduce((acc, s) => { const key = s.score >= 50 ? "pass" : "fail"; (acc[key] ??= []).push(s.name); return acc; }, {}); // { pass: ["A", "C"], fail: ["B"] }

They chain, and that's the point

const topNames = students .filter(s => s.score >= 50) .sort((a, b) => b.score - a.score) .map(s => s.name); // ["C", "A"]

Each step returns an array, so the next can be attached. Read top to bottom: keep the passers, order by score descending, take the names. That reads almost like the sentence you'd say out loud.

Q3When should you use forEach instead of map?
Show answer

When you want a side effect and no result — logging, updating the DOM, pushing to something external. forEach returns undefined.

Using map and discarding the result builds a whole array for nothing and misleads the reader into looking for a return value that never gets used.

The rest of the array toolkit

worth knowing they exist
find(fn)The first matching element, or undefined. Use instead of filter(…)[0] — it stops early.
findIndex(fn)Its position, or -1.
some(fn)Is at least one true? Stops at the first hit.
every(fn)Are all true? Stops at the first miss. Note: [].every(…) is true.
flat(depth)Flatten nested arrays one level, or more with a depth argument.
flatMap(fn)map then flat(1). Handy when each item produces zero or several results.
Array.from(x)Turn an array-like or iterable into a real array. Array.from(document.querySelectorAll("p")) is the classic — a NodeList has no .map.
Array.from({length: n}, fn)Generate an array of n items. Array.from({length: 5}, (_, i) => i) → [0,1,2,3,4].
toSorted / toReversedNon-mutating versions of sort and reverse. Newer, and a genuine improvement.

Set, for uniqueness

const unique = [...new Set([1, 2, 2, 3, 3])]; // [1, 2, 3]

A Set holds only distinct values. Round-tripping through one is the idiomatic way to deduplicate an array of primitives. (It uses identity, so it won't deduplicate objects with equal contents — section 09 again.)

Do this now — chain them on real page data

In the console on any content-heavy page:

Array.from(document.querySelectorAll("a")) .map(a => a.href) .filter(href => href.startsWith("https")) .filter((href, i, arr) => arr.indexOf(href) === i) .sort();

Every unique external link on the page, sorted. Five lines, no loops, and it works on any site you like.

15

Methods and this

chapter 6 — read this one twice

A method is just a function stored as a property of an object. The interesting part is this.

The rule that explains everything

this is determined by how a function is called, not where it was written.

Every confusing this bug comes from expecting the opposite.

const student = { name: "Utkarsh", greet() { return `Hi, ${this.name}`; } }; student.greet(); // "Hi, Utkarsh" — called ON student const fn = student.greet; // pull the function out… fn(); // "Hi, undefined" — no object, no `this`

The function didn't change. Only the way it was called did — and this is whatever appears to the left of the dot at the call site. With nothing to the left, there's nothing to bind.

The four call patterns

obj.method()this is obj. The common case.
standalone()this is undefined in modules and strict mode, the global object otherwise. Almost always a bug.
new Thing()this is the freshly created object. Section 17.
fn.call(obj) / .apply(obj) / .bind(obj)You choose this explicitly. bind returns a new permanently-bound function.

The callback trap

const timer = { seconds: 0, start() { setInterval(function () { this.seconds++; // `this` is NOT timer here }, 1000); } };

setInterval calls your function with no object attached, so this isn't timer. Three fixes, in order of how you should prefer them:

// 1. arrow function — inherits `this` from where it was WRITTEN. Best. setInterval(() => { this.seconds++; }, 1000); // 2. bind — pin `this` permanently setInterval(function () { this.seconds++; }.bind(this), 1000); // 3. the old trick you'll see in legacy code const self = this; setInterval(function () { self.seconds++; }, 1000);

This is the actual reason arrow functions exist

An arrow function has no this of its own. It uses whatever this meant in the surrounding code at the point it was written — so it can't be detached from its context.

Which also means: don't use an arrow function as an object method. { name: "A", greet: () => this.name } doesn't work, because there's no enclosing method for it to inherit from.

Do this now — see all three behaviours

const obj = { name: "object", regular() { return this?.name; }, arrow: () => this?.name }; obj.regular(); // "object" obj.arrow(); // undefined — no enclosing method const loose = obj.regular; loose(); // undefined — detached loose.call(obj); // "object" — this, chosen explicitly
Q4You pass obj.method as an event handler and this comes out wrong. Two ways to fix it?
Show answer

1. Wrap it in an arrow: addEventListener("click", () => obj.method()) — now it's called on obj.

2. Bind it: addEventListener("click", obj.method.bind(obj)).

The cause is always the same: passing obj.method passes the bare function, and the dot — which is what supplied this — is left behind.

16

Prototypes

what's under class

JavaScript has no classes in the way Java does. It has prototypes, and class is a nicer syntax written on top of them. Knowing this is the difference between using classes and understanding them.

The mechanism

Every object has a hidden link to another object, its prototype. Ask for a property the object doesn't have and JavaScript follows that link, and keeps following until it finds the property or runs out of chain.

Do this now — walk a chain by hand

> const arr = [1, 2, 3] > arr.hasOwnProperty("map") false // not on the array itself > Object.getPrototypeOf(arr) === Array.prototype true > Array.prototype.hasOwnProperty("map") true // there it is > Object.getPrototypeOf(Object.prototype) null // top of the chain

Two ways to make an object with a chosen prototype

const proto = { greet() { return `Hi, ${this.name}`; } }; const a = Object.create(proto); a.name = "Utkarsh"; a.greet(); // "Hi, Utkarsh" — greet lives on proto const bare = Object.create(null); // no prototype at all — a clean dictionary

Never modify built-in prototypes

Adding a method to Array.prototype affects every array everywhere, including in libraries you didn't write. Two libraries doing it differently is a genuinely awful debugging session. It also breaks for…in loops across the whole program.

The term for this is "monkey patching", and the correct number of times to do it is zero.

17

Classes

the syntax on top
class Student { #secretNote = ""; // private field — # is part of the name static count = 0; // on the class, not on instances constructor(name, roll) { this.name = name; // runs on `new` this.roll = roll; Student.count++; } greet() { // goes on Student.prototype return `Hi, ${this.name}`; } get label() { // accessed like a property return `${this.name} (${this.roll})`; } static fromCSV(line) { // alternative constructor const [name, roll] = line.split(","); return new Student(name, roll); } } const s = new Student("Utkarsh", "CS2024"); s.greet(); // "Hi, Utkarsh" s.label; // "Utkarsh (CS2024)" — no brackets, it's a getter Student.count; // 1

What new actually does

  1. Creates an empty object.
  2. Sets its prototype to Student.prototype.
  3. Runs the constructor with this bound to the new object.
  4. Returns it.

Four steps, all of which you could do by hand with Object.create. That's the sense in which class is sugar — it isn't a different object system, just a readable way to set up the same prototype links.

Do this now — prove methods live on the prototype

> s.hasOwnProperty("name") true // instance data: on the object > s.hasOwnProperty("greet") false // method: NOT on the object > Object.getPrototypeOf(s) === Student.prototype true // it's up there

Ten thousand students share one copy of greet. That's the efficiency prototypes buy, and it's invisible until you look for it.

Private fields (#)Genuinely inaccessible from outside — a real language feature, not a naming convention like the old _private.
staticBelongs to the class itself. Useful for counters, constants and factory methods like fromCSV above.
get / setLook like properties, run like functions. Good for derived values; avoid putting expensive work in them, since callers won't expect a cost.
Not hoistedUnlike function declarations, you can't use a class before you define it.
18

Inheritance, and composition

and when not to use it
class Person { constructor(name) { this.name = name; } greet() { return `Hi, ${this.name}`; } } class Student extends Person { constructor(name, roll) { super(name); // MUST come before using `this` this.roll = roll; } greet() { return `${super.greet()} (${this.roll})`; // extend the parent's } }
extendsLinks the prototype chains, so instances find parent methods automatically.
super(...)Calls the parent constructor. Required before touching this in a subclass constructor.
super.method()Calls the parent's version — how you extend rather than replace.
instanceofs instanceof Person is true: it walks the prototype chain.

Prefer composition to inheritance

Inheritance couples a subclass tightly to its parent's internals. Change the parent and every descendant can break in ways you can't see from the file you edited. Deep hierarchies — four or five levels — are notoriously hard to reason about, and this is a lesson the industry learned the hard way in the 2000s.

The test: use inheritance only when the subclass genuinely is a more specific kind of the parent, and you'd be comfortable using it anywhere the parent is expected. A Student is a Person, so that's fair. A Car is not an Engine — it has one.

Most of the time, holding an object as a property and delegating to it is simpler, more flexible and easier to test.

// composition — a Car HAS an engine rather than IS one class Car { constructor(engine) { this.engine = engine; } start() { return this.engine.start(); } }

And often you need neither

A plain object plus a few functions that take it as an argument is a perfectly good design, and frequently a better one. Modern JavaScript — especially React — leans heavily this way. Classes are a tool, not a requirement.

Modern conveniences

small things, used constantly
// optional chaining — stop instead of throwing student?.address?.city // undefined if any link is null/undefined student.greet?.() // only call if it exists list?.[0] // works on indexes too // nullish coalescing — a default for null/undefined ONLY const port = config.port ?? 3000; const port = config.port || 3000; // ✗ also replaces 0 and "" // logical assignment counts[key] ??= 0; // assign only if null/undefined // template literals `${name} scored ${score}/100` `multi line`

?? and || are not interchangeable

|| falls back on any falsy value — so 0, "" and false all trigger the default. If a user sets a quantity to 0 and your code says qty || 1, you've just silently changed their zero to a one.

?? only falls back on null and undefined. For defaults on user data, it's almost always the correct one.

Modules, briefly

// utils.js export function formatName(s) { … } export default class Student { … } // main.js import Student, { formatName } from "./utils.js";

In the browser this needs <script type="module" src="main.js">. Modules are deferred automatically, are always in strict mode, and have their own top-level scope — so nothing leaks into the global namespace.

What comes next

The natural sequel to this material is asynchronous JavaScript — promises, async/await, and fetch — which is how you talk to a server. It's Eloquent JS chapter 11, and every single thing in it rests on the higher-order functions in section 12: a promise's .then takes a callback, and that's the whole idea.

Debugging in DevTools

better than console.log

console.log is fine and you'll use it forever. But the debugger answers questions that logging can't, and most people never learn it.

Do this now — set a breakpoint

  1. DevTools → Sources tab → find your main.js in the file tree.
  2. Click a line number. It turns blue — that's a breakpoint.
  3. Reload or trigger the code. Execution pauses on that line.
  4. Look at the Scope panel on the right: every variable in scope, with its current value. No logging required.
  5. Hover any variable in the source to see its value inline.
  6. Use the step buttons: step over (next line), step into (go inside a call), resume.
The Scope panelShows Local, Closure and Global scopes separately — which makes section 05 concrete. You can literally see the captured variables.
The Call Stack panelHow you got here, frame by frame. Click any frame to inspect it. Section 06 made visible.
Conditional breakpointsRight-click a line number → Add conditional breakpoint → i === 42. Only pauses when it matters, which beats logging a thousand iterations.
debugger statementPut the word debugger; in your code and it acts as a breakpoint. Remember to remove it.
Pause on exceptionsThe ⏸ icon with a stop sign. Execution halts wherever an error is thrown, with the full state intact. Extremely useful.

Reading an error message properly

TypeError: Cannot read properties of undefined (reading 'name') is not vague — it's precise. It says: something was undefined, and you tried to read .name from it.

So the bug is not on the line that mentions name. It's wherever that thing was supposed to get a value. Read the stack trace below the message from the top: the first line in your file is where to look.

When it goes wrong

the usual suspects
Cannot read properties of undefinedSomething in the chain doesn't exist. Log the parent, not the property. Use ?. if it's legitimately optional.
x is not a functionUsually a typo (lenght), or it's not the type you think — querySelectorAll returns a NodeList with no .map. Check with typeof.
My object changed by itselfSomething else holds a reference to it. Section 09.
Spread copy still shares dataSpread is shallow. Nested objects are shared. Use structuredClone.
this is undefinedThe function was detached from its object. Use an arrow function or bind. Section 15.
My arrow method can't see thisArrow functions have no this — don't use them as object methods.
sort() gave nonsenseDefault sort is alphabetical. Pass (a, b) => a - b for numbers.
My array is empty after mappingThe callback has braces but no return, so every item is undefined.
reduce gave the wrong answerMissing initial value. Always pass one.
The handler fires immediatelyYou wrote onClick(handler()) instead of onClick(handler). Section 12.
0 or "" became my default|| treats them as falsy. Use ??.
querySelector returns nullThe script ran before the HTML existed. Add defer. Or the selector is wrong — test it in the console.
Maximum call stack size exceededInfinite recursion. Your base case is missing or never reached.
NaN appearedArithmetic on something that isn't a number — often a string from an input field. Number(x) or parseInt(x, 10) first.

The general method

1. Read the error and the stack trace. Find the first line that's in your own code.

2. Log the thing before the failure, not the failure itself.

3. Check types with typeof and Array.isArray — most bugs are something being a different type than you assumed.

4. Set a breakpoint and look at the Scope panel rather than adding a sixth console.log.

Asking for help is a skill, not a failure

When you're stuck, ask — and bring the exact error message, the line it points at, and what you expected to happen. Those three things resolve most questions in under a minute. "My code doesn't work" cannot be answered by anyone.

Final checkpoint

answer before revealing

Fifteen questions. Answer each in your head — or better, out loud — before opening the answer. Several of these are standard interview questions.

1Explain const to someone who thinks it means immutable.
Show answer

It stops the binding being reassigned, not the value being changed. const list = [1,2]; list.push(3) is fine; list = [4] throws.

For actual immutability you need Object.freeze, or the discipline of never mutating.

2Why is let preferred over var? Give two reasons.
Show answer

var is function-scoped so it leaks out of blocks; and it hoists as undefined, so using it too early fails silently instead of throwing.

let is block-scoped and throws a ReferenceError if used before its declaration — failing loudly is better.

3What is a closure, in one sentence?
Show answer

A function together with the scope it was created in, which it keeps access to even after that scope has finished executing.

Which is how makeCounter gives each returned function its own private, persistent count.

4for (var i…) with setTimeout logs 3,3,3. Why, and what fixes it?
Show answer

var creates one binding shared by all three closures. By the time the timeouts fire, the loop has finished and i is 3.

let creates a fresh binding per iteration, so each closure captures its own — giving 0, 1, 2.

5What's the difference between slice and splice?
Show answer

slice returns a copy of a portion and leaves the original alone. splice removes and/or inserts in place, mutating the original, and returns what it removed.

6Why does [10, 9, 1].sort() give [1, 10, 9]?
Show answer

The default comparator converts elements to strings, and "10" sorts before "9" alphabetically.

Pass a comparator: .sort((a, b) => a - b). Also remember it mutates — copy first with [...arr] if that matters.

7Why is {a: 1} === {a: 1} false?
Show answer

Objects are compared by identity, not contents. Those are two distinct objects that happen to look alike.

8You spread-copy an object and change a nested property — the original changes too. Why?
Show answer

Spread is a shallow copy. Top-level primitives are copied, but nested objects are copied by reference, so both objects point at the same nested one.

Use structuredClone(obj) for a deep copy.

9When do you need bracket notation instead of a dot?
Show answer

When the property name is in a variable, computed at runtime, or isn't a valid identifier. obj[key] uses the variable's value; obj.key looks for a property literally called "key".

10Distinguish map, filter and reduce in one line each.
Show answer

map — same number of items, each transformed. filter — fewer items, each unchanged. reduce — everything collapsed into a single value.

And always pass reduce an initial value.

11What determines the value of this?
Show answer

How the function is called, not where it was defined. obj.method() → obj. A bare call → undefined in strict mode. new → the new object. call/apply/bind → whatever you specify.

Arrow functions are the exception: they have no this and inherit it from where they were written.

12Why should you not use an arrow function as an object method?
Show answer

It has no this of its own, so it inherits from the enclosing scope — which at the top level of an object literal isn't the object. this.name will be undefined.

Arrows are right for callbacks inside methods, which is the opposite situation.

13What happens when you access a property an object doesn't have?
Show answer

JavaScript follows the object's prototype link and looks there, then at that object's prototype, and so on until it finds the property or reaches null. If nothing matches, you get undefined.

That chain is why every array has .map without you defining it.

14Where do class methods actually live?
Show answer

On ClassName.prototype, not on each instance — which is why instance.hasOwnProperty("method") is false.

Ten thousand instances share one copy of each method. class is syntax over prototypes, not a separate system.

15Why prefer ?? over || for defaults?
Show answer

|| falls back on any falsy value, so a legitimate 0, "" or false gets silently replaced. ?? only falls back on null and undefined.

quantity || 1 turns a user's deliberate 0 into 1. quantity ?? 1 doesn't.
