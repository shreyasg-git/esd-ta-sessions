Recap — functions are values

  • A function can be stored in a variable, passed around, returned from another function
  • This one idea is the foundation of everything today
const shout = (s) => s.toUpperCase(); shout; // the function itself — a value shout("hi"); // calling it — the result

Higher-order functions

Definition

A function that takes a function as an argument, or returns one.

map, filter, reducetake a function
setTimeout, addEventListenertake a function
makeCounter() factoriesreturn a function
["a", "b"].map(shout); // ✓ pass the function ["a", "b"].map(shout()); // ✗ calls it now, passes the result
03

Three higher-order examples

two that take, one that returns

Example 1 — takes a function: setTimeout

function sayHi() { console.log("Hi!"); } setTimeout(sayHi, 2000); // pass sayHi itself, don't call it
  • setTimeout is higher-order because you don't call sayHi — you hand it over, and the browser calls it later
  • Same shape as ["a","b"].map(shout) from the last section

Example 2 — takes a function: addEventListener

function handleClick() { console.log("button was clicked"); } button.addEventListener("click", handleClick);
  • addEventListener takes a function and calls it whenever the event happens — could be never, could be a hundred times
  • This is the pattern you'll use constantly for the Marks Calculator's Calculate button

Example 3 — returns a function: makeCounter

function makeCounter() { let count = 0; return function () { // this function is the return value count += 1; return count; }; } const counter = makeCounter(); // counter is now a function counter(); // 1 counter(); // 2
  • makeCounter is higher-order because it returns a function instead of a number or string
  • We'll unpack exactly how this works below — this is a closure

map / filter / reduce — recap

const scores = [80, 45, 92, 30]; scores.map(s => s * 2); // same length, transformed scores.filter(s => s >= 50); // fewer items scores.reduce((sum, s) => sum + s, 0); // one value — always pass init
mapsame count, each item transformed
filterfewer items, each unchanged
reducecollapses to one value
05

Write your own HOF

  • Any function can accept a function as a parameter
function repeat(n, action) { for (let i = 0; i < n; i++) action(i); } repeat(3, i => console.log("run", i));
  • This is exactly how map / filter / forEach are built internally

Closures — the idea

Definition

A closure is a function that keeps access to the variables from the scope it was created in — even after that outer scope has already finished running.

  • Normally, when a function finishes running, its local variables are thrown away
  • But if that function returns another function, and that inner function uses those variables, they aren't thrown away
  • The inner function keeps a live connection to them — that connection is what we call a closure
07

The simplest possible example

function greet(greeting) { return function (name) { return `${greeting}, ${name}!`; }; } const sayHello = greet("Hello"); sayHello("Utkarsh"); // "Hello, Utkarsh!" sayHello("Priya"); // "Hello, Priya!"
  • greet("Hello") runs once and finishes — greeting should be gone
  • But the inner function still refers to greeting, so it stays alive
  • Every time you call sayHello, it still has access to "Hello"
08

Walking through makeCounter

function makeCounter() { let count = 0; // ① created once return function () { // ② this is what gets returned count += 1; // ③ reads/updates the packed variable return count; }; } const counter = makeCounter(); counter(); // 1 counter(); // 2 counter(); // 3

Step by step

  1. makeCounter() runs, creates count = 0, then returns the inner function
  2. Normally count would now be thrown away — its function is done
  3. But the returned function still refers to count, so it survives
  4. Each call to counter() updates that same count
09

Each call creates a separate copy

const a = makeCounter(); const b = makeCounter(); a(); // 1 a(); // 2 b(); // 1 ← starts fresh, doesn't know about a's count
  • a and b come from two separate calls to makeCounter()
  • Each call creates its own count, independent of the other
  • Nothing outside can read count directly — the only way to reach it is through the function that closed over it

Why closures matter

Private statecount can't be reached or corrupted from outside
Function factoriesbuild specialised functions from a general one (multiplyBy(2) → double)
Callbacks that rememberan event handler that still knows which item it belongs to
function multiplyBy(factor) { return (n) => n * factor; // this arrow function closes over `factor` } const double = multiplyBy(2); double(7); // 14

this — the rule

The rule

this is determined by how a function is called, not where it was written.

const student = { name: "Utkarsh", greet() { return `Hi, ${this.name}`; } }; student.greet(); // "Hi, Utkarsh" — called ON student const fn = student.greet; fn(); // "Hi, undefined" — no object, no this
12

The four call patterns

it depends on how you call it

A function's this isn't fixed — the same function can get a different this depending on how it's called. There are four ways this plays out:

1Called on an object → obj.method()
2Called standalone → fn()
3Called with new → new Thing()
4Called with call / apply / bind

Let's look at each one with code.

Pattern 1 — called on an object

const student = { name: "A", greet() { return this.name; } }; student.greet(); // "A"
  • student.greet() is called on student — that's what's to the left of the dot
  • So inside greet, this becomes student, and this.name is "A"

Pattern 2 — called standalone

function whoAmI() { return this; } whoAmI(); // undefined
  • Here the function is just called by itself — whoAmI(), nothing to the left of a dot
  • With nothing attached, there's no object for this to point to, so it's undefined
  • This is the case that usually causes the "this is undefined" bug

Pattern 3 — called with new

function Student(name) { this.name = name; } const s = new Student("A"); s.name; // "A"
  • new creates a brand-new empty object first
  • It then runs Student with this bound to that new object
  • So this.name = name sets name on the object new just created

Pattern 4 — called with call / apply / bind

function greet() { return this.name; } greet.call({ name: "A" }); // "A"
  • call lets you say exactly what this should be, instead of relying on the call site
  • apply does the same thing but takes arguments as an array
  • bind doesn't call the function immediately — it returns a new function with this permanently set
13

this — the callback trap

setInterval(function () { this.seconds++; // this is NOT what you expect here }, 1000);

Fix — use an arrow function

setInterval(() => { this.seconds++; // inherits this from where it was written }, 1000);
  • Arrow functions have no this of their own — that's the whole reason they exist

Async JavaScript

14

Why async?

  • JavaScript runs on a single thread — one thing at a time
  • Some tasks take time: network requests, timers, file reads
  • Blocking that thread while waiting would freeze the whole page
  • Async lets JS start a task, keep running other code, and handle the result later
15

Callbacks — the old way

setTimeout(() => { console.log("done waiting"); }, 1000);
  • A function passed in to be called later, once something finishes
  • Works, but nesting many of them gets messy fast
16

Callback hell

getUser(id, (user) => { getOrders(user, (orders) => { getInvoice(orders, (invoice) => { console.log(invoice); // deeper and deeper... }); }); });
  • Each step nests inside the last — hard to read, hard to handle errors
  • Promises exist to fix exactly this
17

Promises

Definition

An object representing a value that isn't ready yet, but will be (or will fail).

A promise is always in one of three states:

pendingstill waiting
fulfilledsucceeded, has a value
rejectedfailed, has a reason
18

Creating and using a Promise

const wait = new Promise((resolve, reject) => { setTimeout(() => resolve("done!"), 1000); }); wait.then(result => console.log(result)); // "done!"
  • resolve(value) → moves to fulfilled
  • reject(error) → moves to rejected
19

Chaining with .then / .catch

getUser(id) .then(user => getOrders(user)) .then(orders => getInvoice(orders)) .then(invoice => console.log(invoice)) .catch(err => console.error("failed:", err));
  • Same steps as callback hell — now flat, readable top to bottom
  • One .catch handles errors from any step in the chain
20

async / await

  • Syntax sugar over promises — write async code that reads like sync code
  • async in front of a function makes it always return a promise
  • await pauses that function until the promise settles
async function getData() { const result = await wait; console.log(result); }

Side by side

Promise style:

getUser(id).then(user => console.log(user));

async/await style:

async function loadUser(id) { const user = await getUser(id); console.log(user); }
  • Same behaviour, flatter and easier to follow
21

Error handling with async/await

async function loadInvoice(id) { try { const user = await getUser(id); const orders = await getOrders(user); const invoice = await getInvoice(orders); return invoice; } catch (err) { console.error("failed:", err); } }
  • try/catch replaces .catch — familiar, synchronous-looking error handling
22

fetch() — a real example

async function loadCourses() { const response = await fetch("/api/courses"); const data = await response.json(); console.log(data); }
  • fetch returns a promise
  • This is exactly how the frontend will talk to a backend later in the course

JS — reading inputs & calculating

document.getElementById("calc").addEventListener("click", () => { const s1 = Number(document.getElementById("s1").value); const s2 = Number(document.getElementById("s2").value); const s3 = Number(document.getElementById("s3").value); const total = s1 + s2 + s3; const average = total / 3; const passed = [s1, s2, s3].every(s => s >= 35); // update the DOM with total, average, passed... });
  • Notice .every() from the array toolkit — a higher-order function in action

JS — validation

function isValid(...marks) { return marks.every(m => !isNaN(m) && m >= 0 && m <= 100); }
  • Empty field → Number("") is 0, so also check the raw input isn't blank
  • Show a clear error message instead of computing on bad input
